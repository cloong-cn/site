想要一个自己的网站很久了。用过几个现成的博客程序，总有些地方不顺手：主题改起来要先学一套模板语法，
插件一多就慢，数据放在别人的平台上也不踏实。最后决定自己写一个，要求只有三条：

- **快**：访客打开的是现成的静态页面，不在服务器上临时拼。
- **能自己掌控**：代码、文章、图片、数据库都在自己的服务器上，换地方的时候整个搬走。
- **好看，但不花哨**：参照苹果和 SpaceX 的网页，干净、留白多、细节到位。

这篇按做的顺序记下来，也算是这个网站的说明书。

## 整体结构

网站分成两半：访客看到的全是**静态文件**，写文章和评论这两件需要“动”的事交给**两个 Java 小服务**。

```text
             ┌───────── 我在后台写 ─────────┐
             ▼                              │ 只有我知道的地址
   PostgreSQL（文章、历史版本、评论）    后台服务（Java）
             │ 点「发布」                    │
             ▼                              │
  导出文章 → Node 构建静态页面 → /srv/blog/live ◀── Nginx ◀── 访客
                                                 │ /api/comments
                                                 ▼
                                       评论服务（Java）── PostgreSQL
```

这样分有一个很实在的好处：数据库或者 Java 服务停了，文章照样能看，只有评论区会暂时隐藏。

## 不用前端框架

页面模板就是普通的 JavaScript 模板字符串，构建脚本 `scripts/build.mjs` 读 Markdown、套模板、写出 HTML。
整个前端只依赖三个包：`marked` 解析 Markdown，`highlight.js` 做代码高亮，`sharp` 处理图片。

不用框架不是为了标新立异，而是这个网站本来就不需要：页面上没有复杂的状态，几个交互（翻页、目录、图片全屏、评论）
各写一个小脚本就够了。结果是首页的 JavaScript 只有十几 KB，关掉 JavaScript 也能正常阅读。

> [!TIP]
> 代码高亮是在构建时做好的，配色照着 Xcode 的默认主题，亮色暗色各一套。访客不用为它多下载任何脚本。

## 图片：只下载用得到的那一张

文章里的每张图片在构建时都会：

1. 缩成 480、800、1200、1600 四种宽度；
2. 转成 AVIF 和 WebP，浏览器挑自己支持的、适合屏幕的那一张；
3. 写好宽高，加载时页面不会跳；
4. 去掉 EXIF 里的拍摄地点和手机型号。

处理结果缓存在 `.cache/` 里，同一张图只处理一次。

## 中文字体：只切用得到的字

这是最近才加上的。苹果设备上中文用的是苹方，本来就很好看；但在 Windows 上会落到微软雅黑，
小字号时边缘发虚，笔画也不够饱满。

想换成思源黑体，问题是一套中文字体有好几 MB。解决办法是**只切用得到的字**：构建时统计每一页出现的汉字，
很多页面都用到的字放进一个共用文件，缓存之后换页不用再下；其余的字每页单独切一小份。

```js title="scripts/fonts.mjs"
async function cut(chars, weight) {
  const text = [...chars].sort().join('');
  const key = createHash('sha256').update(`${weight}:${text}`).digest('hex').slice(0, 12);
  // 同样的字、同样的字重只切一次，结果缓存在 .cache/fonts
  buf = await subsetFont(font, text, { targetFormat: 'woff2', variationAxes: { wght: weight } });
}
```

字重也分两种：常规字重覆盖所有的字，半粗字重只包含标题和加粗文字里的字。
苹果设备继续用系统自带的苹方，什么都不下载。

## 上线：git push 就够了

服务器上有一个 Git 仓库，推送代码后钩子自动构建。构建到一个带时间戳的新目录，成功了才把网站指过去：

```bash title="deploy/build-site.sh"
# 先建好新的链接，再用 rename 一步替换：访客不会遇到“换到一半”的状态
ln -sfn "$BUILDS/$stamp" "$BASE/.live.new"
mv -T "$BASE/.live.new" "$BASE/live"
```

构建失败什么都不变，网站还是上一个版本。最近 5 个版本都留着，后台里点一下就能切回去。

> [!NOTE]
> 文章不在 Git 仓库里，而是存在数据库中，所以代码可以放心开源，草稿不会跟着出去。

## 后台和安全

后台在一串随机生成的地址下面，登录要密码加手机验证码。常见的后台地址，比如 `/admin/`、`/wp-login.php`，
放的是一个永远登录不进去的假登录页，用来记录每天来试探的扫描器。

两个 Java 服务都不依赖任何第三方库，连 PostgreSQL 的通信协议都是自己实现的，几百行代码。
这样做最大的好处是：不会因为某个依赖爆出漏洞而被迫升级。

## 把主页删到只剩要紧的

做到后来，主页越来越满：首屏底下有一条仿 SpaceX 直播的遥测条，弧线、时钟、四个仪表盘；
每一屏都有编号和巨大的标题；文章、作品、服务都套着带阴影的卡片。每个单独看都不错，放在一起就吵了。

这一次的改法只有减法：

- 遥测条缩成角落里的一行小字：城市、时间、气温、下一次日落；
- 标题从 84 像素缩到正文大小，首屏的名字成了页面上唯一的大字；
- 卡片全部去掉，换成一条 1 像素的分隔线；
- 整页只用三种字号，可以点的东西只用一种颜色，也就是苹果的链接蓝。

改完再看，内容本身反而更清楚了。留白不是浪费空间，它告诉你哪些东西是一组的。
